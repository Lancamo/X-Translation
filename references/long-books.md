# long-books.md — 500 页以上的长书：调度、一致性、验收

> 本文来自一次大部头文档的规模压力测试（800+ 页学术专著）：
> 1.5 万+ 个文本单元，其中 4,000+ 个待译，87 批翻译，成品保留全部页数与全部书签。
> 90 页设计稿的那一套做法在 800 页上会**在三处失效**，本文只写这三处，
> 通用部分仍看 `workflow.md` 与 `pitfalls.md`。

---

## 一、规模改变的不是工作量，是失效模式

| 维度 | 90 页设计稿 | 800 页学术书 |
|---|---|---|
| 构建 | 一次跑完，几分钟 | 一次跑完会失败 → **必须分块** |
| 一致性 | 一人翻完，天然一致 | 几十批并行翻 → **同一源串必然出现多种译法** |
| 可见性 | 肉眼扫一遍能发现空白 | **整段被丢弃也看不出来**，只能靠报表字段 |
| 文本性质 | 多为标题 / 图注 / 短句 | 大段正文、数学公式、参考文献、索引，各有各的口径 |

**记住这张表**：长书多出来的工作量不在"翻译"，在"调度 + 归一 + 可观测"。

---

## 二、构建：分块，否则跑不完

全量 `24_rebuild_text.py` 在大部头（500 页以上）上会跑不完。做法是**按 50 页分块，再合并**：

```python
# 每块：取源 PDF 的 [i:i+50] 页 → 走同一条回填管线 → 出 _chunk_a_b.pdf
# 合并：建空文档，逐块 insert_pdf，最后统一重建书签
```

三个必须守住的点：

1. **每块独立出 report**，合并成一份 `rebuild_report.json`。没有这份报表，
   后面所有的质量判断都没有依据（见第五节）。
2. **书签在合并之后重建**，不要指望块级保留——块的页码是相对页码。
3. **分块只改变执行顺序，不改变任何排版参数**。若分块结果与全量不一致，
   那说明有状态泄漏（字体缓存 / 基线标定），先查这个再查别的。

实测：800+ 页 / 17 块，约 8 分钟。

## 三、翻译：子 agent 分批 + 两张冻结表

### 分批

- 4,192 个待译单元切成 **87 批**，每批 30–80 条，交给子 agent。
- 每批独立落 `work/text_queue/trans_NNN.json`，**不要直接改总表**——
  批次失败时可以单独重跑，不会污染其它批次。
- 触发 429 限流时：换 `lite` 模型 + 缩短 prompt + 拆更小的批，不要硬重试。

### 合并后必须校验四项，全 0 才算过

```
missing（有单元没译文） / extra（有译文没单元） / empty（空串） / conflicts（同键不同值）
```

实测 87 批合并：4,192 键，四项全 0。**这一步不做，后面所有验收都是在沙上建塔。**

### 两张冻结表（先冻结，再翻译）

| 表 | 管什么 | 谁定 |
|---|---|---|
| `glossary.json` | 术语：`keep`（保留英文）/ `fixed`（固定中文） | 开工前与用户确认，之后不再动 |
| `nav_table.json` | 页眉 / 目录页的**固定译法**，单元 text 精确命中就照抄 | 同上 |

实测：术语 75 条（keep 10 / fixed 65），导航 123 条。

**口径必须在翻译前与用户确认清楚**，一条都别自己猜。这次确认下来的是：

- 导航文字（页眉 / 目录 / 图表标签）→ 整译中文
- 结构词：`Appendix/Addendum` → 附录/第 N 章附录；`Section` → 节；
  `Proposition / Table / Figure / Lemma / Corollary / Assumption` → **保留英文**
- 正文 keep 只留人名与专名（Wicksellian、Taylor rule、Phillips curve、Calvo pricing…）
- **参考文献、索引整体保留英文**（只有页眉"REFERENCES"译中文）

最后一条最关键：不先定，验收时 18 页参考文献会被当成"漏译"反复调查。

## 四、一致性：长书最大的质量风险

### 症状

分批翻译必然产生两类不一致：

1. **同一源串多种译法**——正文 p114 与附录 p658 是同一个 Proposition，译出了两版。
2. **结构词时中时英**——全书 195 处 `Figure`，126 处保留英文、71 处译成"图"。

第 2 类最伤读者：目录与正文对不上，正文前后对不上。

### 归一化的做法（顺序不能乱）

```python
# 1) 结构词：只对「中文词 + 小节号」下手，避免误伤普通用词
图\s*(\d+\.\d+)   -> Figure \1        # 命中 127 处 / 73 单元
命题\s*(\d+\.\d+) -> Proposition \1   # 10 处
假设\s*(\d+\.\d+) -> Assumption \1    # 21 处
表\s*(\d+\.\d+)   -> Table \1         # 17 处
# 2) 结构词后的中文句号改英文句点（多数派风格）
(Proposition|Assumption|Table|Figure)\s*(\d+\.\d+)。 -> \1 \2.
# 3) 中英之间补空格（"见表 1.1" -> "见 Table 1.1"）
([\u4e00-\u9fff])(Figure|Table|Proposition|Assumption)\b -> \1 \2
```

**归一化之后必须同步三处**，否则会连环翻车：

- `nav_table.json` 里的对应条目（目录页用的是冻结表，不跟着改就对不上）
- 书签映射的兜底表
- **书签映射要求译文含中文**，全英文译文会直接报 `Cannot map bookmark safely`

### ⚠ 归一 / 合并脚本必须带 guard（这次真实踩到）

统一"重复源串"时写了 `norm(src)` 分组，`norm()` 会把非字母数字全剥掉，
于是**源串为空的条目全被归到一组**，脚本把 9 个 `inflation`（正确译"通货膨胀"）
一起改成了提取碎片"通货膨"。发现得早，靠批次文件回滚才没酿成事故。

三条硬 guard：

1. 分组键归一化后为空 → **跳过整组**。
2. 同组译文长度相差悬殊 → 短的那个是**提取碎片**，不是另一种译法，取最长的。
3. 命中冻结导航表的译法优先（字母间距版 `R E F E R E N C E S` → `参 考 文 献`，
   与普通 `References` → `参考文献` 是**两回事**，强行统一反而错）。

**改完立刻做差异复核**：列出所有与批次原文不同的单元，确认无一"明显变短"。

## 五、装框：窄框单行整段被静默丢弃（最隐蔽的坑）

### 症状

成品里少了一句、少了一行，**渲染图上看就是空白**，报表不看不出来。

### 根因（MuPDF 1.28）

中文通常比英文源宽 4–20%。`insert_htmlbox` 的行为是：

1. 先按 `scale=1.0` 排版，发现一行装不下 → 排成 2 行；
2. 再整体缩放到框内；
3. 若 2 行所需高度 > `box_h / scale_low` → **整段丢弃**（`spare = -1`，没有任何报错）。

框越窄、下方越紧（下一行紧跟），越容易触发。单句、图注标题、行内公式最常中招。

### 修法

```python
# 1) 单行单元：按字体度量预估宽度，先缩到能排成 1 行
w = sum(Font.text_length(seg, size) for seg in spans(text))
if w > box.width * 0.82:            # --width-floor 0.82
    size *= (box.width * 0.82) / w
# 2) 框高至少容得下一行，否则第 1 步算出来也白搭
box.y1 = max(box.y1, box.y0 + lhr * size * 1.02)
```

### 门禁（硬）

`rebuild_report.json` 必须带 `spare / box_w / box_h / lhr` 四个字段，
**交付前断言 `spare < 0` 的条目数 == 0**。实测修前 41 处自动缩放、若干丢弃，
修后 9 处缩放、**0 处丢弃**。

> 这一条是本轮最大的收获：**"没有文字"是不会报错的失败**，
> 只能靠报表字段兜住。任何回填管线都应该先把 `spare` 记下来。

## 六、验收：页级比对 + 红项定性

### 页级比对（长书专用）

逐页算两个数：源页英文词数、成品页中文字数。

```
源英文词 >= 25 且成品中文 < 10  →  列入可疑
```

实测出的可疑页集中在参考文献区，共 18 页 —— 全是参考文献，**按第三节的口径是有意保留**。
先定口径再跑，这 18 页就不会反复调查。

同时确认：**没有任何一页"源有英文、成品几乎无文字"**（实测定 0），
这条能兜住"整块丢失"这类灾难。

### 红项必须逐项定性，不许笼统说"通过"

`64_audit_text.py` 在长书上会报出一大堆红项，实测 87 项里**没有一项是真缺陷**，
但每一类都要写清楚它是怎么来的：

| 红项 | 数量 | 定性 |
|---|---|---|
| 数字丢失 | 54 | 形近字误判（`3.1I` 里的 `I` 被当 `1`）。**去掉形近字映射重算**，真的只剩 3 处，且是"百分之百"这类中文写法 |
| 冻结术语不符 | 608 | 子串匹配误伤（"通胀" vs "通货膨胀"、"新维克塞尔式"）。合法变体 |
| 字符集损坏 | 11 | 源 PDF 数学字体（MTEX/MTMI）本身没有 ToUnicode。**扫源对照**：源 3,442 / 成品 3,236，属源侧既有现象 |
| 连字 | 65 | `ﬀ/ﬁ` 是标准连字码位，语义等价，只影响按原串搜索 |
| 重复源串不一致 | 20 | 真问题（见第四节），归一化后归零 |

定性结果单独写 `QC_NOTES.md`，与 `QC_REPORT.md` 一起交付。
**只交一份"通过"的总表，等于没验。**

### T0 结构断言

七项全过（页数一致、逐页尺寸、旋转角、书签层级/页码/译文全部对应、章节标题、全部字体嵌入）。
其中 **Type3 字体要按 `CharProcs` 引用的流是否存在且非空**判断"已嵌入"，
按常规 `is_embedded` 判会误 FAIL。

## 七、工作目录约定

每个转换任务一个文件夹，命名 `NN_原PDF文件名`（NN 从 01 起）：

```
工程根/
├── README.md / CLAUDE.md          ← 工程约定，跨项目共享
├── Plan/                          ← skill 设计与优化记录
├── scripts/                       ← 工程主脚本集（打包进 skill 的源）
├── 01_MyReport/                  ← 「NN_原PDF文件名」，NN 从 01 起
│   ├── MyReport.pdf              ← 原 PDF 一并收进来
│   ├── work/                      ← 中间产物、报表、验证
│   └── output/                    ← 成品
└── 02_TheoryOfMoney/
    ├── TheoryOfMoney.pdf
    ├── scripts/                   ← 该任务演进过的脚本（主脚本集的分支）
    ├── work/
    └── output/
```

要点：

- **原 PDF 放进自己的文件夹**，不要散在根目录——它是这个任务的输入凭证。
- 任务里若改过脚本，**演进版留在该任务文件夹**（如 02），主脚本集保持通用。
- `Handoffs/`、`X-Translation_push/` 这类**用途独立的目录不参与重排**。

## 八、成本实测（800+ 页大部头）

| 项 | 数值 |
|---|---|
| 文本单元 / 待译单元 | 15,073 / 4,192 |
| 翻译批次 | 87 批（子 agent 并行，遇 429 换 lite 模型） |
| 分块构建 | 17 块 × 50 页，约 8 分钟 |
| 成品 | 800+ 页，页数与书签全部保留，8.71 MB |
| 自动缩放（scale<0.985） | 9 处 |
| 文字被丢弃（spare<0） | **0** |

翻译本身只占整个工期的一部分；**归一化、回滚、重构建、定性验收**加起来与之相当。
排期时按这个比例估。
