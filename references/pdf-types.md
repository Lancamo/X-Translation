# pdf-types.md — 五类 PDF 的判定与分支

判错类型会导致后面整条管线白跑，所以**第一步永远是侦察**：

```bash
python3 10_probe_pdf.py input.pdf
```

## 判据速查

| 观察项 | 说明 |
|---|---|
| 文字层字符数 / 页 | < 50 → 扫描型；> 500 → 可编辑型 |
| 页面尺寸 | 595×842 (A4) / 612×792 (Letter) → 文档型；720×405、1920×1080 → 设计稿型 |
| 字体 | 全部嵌入且是完整字体 → 矢量型；只有子集（`ABCDEF+` 前缀）→ InDesign/AI 导出 |
| 图片 | 少量大图 → 图表内嵌；每页一张整页图 → 扫描件 |
| 图形对象 | `page.get_drawings()` 数量大 → 图表是矢量的，文字可能也还在文字层 |

## 五类分支

### ① 可编辑型（研报、白皮书、论文）

- 文字层完整、字体嵌入、图表是独立位图
- **走全流程 L0 → L1 → L3 → L2 → L2b → L4**
- 主战场在 L1（正文）和 L2（图表内文字）
- 实测样本：a16z《State of Markets》90 页，文字层 4,395 词，图内文字 3,915 块 / 56,312 字符

### ② 扫描型（影印、拍照件）

- 没有文字层，或文字层是 OCR 垃圾（字符数正常但内容错乱、bbox 全页）
- **跳过 L1**，全部走 L2 覆盖
- 成功率由 OCR 质量决定：先跑 `12_scan_image_text.py` 抽检 5 页
- 注意：扫描件常有倾斜和透视畸变，`bbox` 会偏；先做去斜（`pymupdf` 不直接支持，需 OpenCV 或 `img2pdf` + 图像预处理）
- 图像质量差 → 建议先做增强，否则 OCR 误差会把译文带偏

### ③ 纯矢量型（InDesign / Illustrator 导出）

- 文字层完整但字体是子集，位置精确到 0.01pt
- 走 L1；**重点防"字宽差异撑破文本框"**
- 拉丁字母平均字宽 ≈ 0.5em，汉字 = 1.0em。同一框内中文行数约为英文的 2 倍
- 必须加约束：`起始字号 = min(块高 × 0.78, 框宽 / 字数 × 1.25)`

### ④ 设计稿型（画册、发布会 PPT 导出）

- 半页宽页面（如 720×405pt），大标题常是**透明位图叠在背景照片上**
- L0 就要扫"标题位图"：透明位图（alpha 均值 0.03~0.09）+ 与 ≥18pt 文字块重叠 ≥50% + 高度比 0.5~2.5
- 必须走 L3，否则会出现"大标题没翻译"（其实是译文写在文字层，底下英文位图还在）
- 多数设计稿是**屏幕优先**：字号可以很小（2~3pt）也能看清（放大即可）
  → 小字要不要翻，见 SKILL.md 第四节的微标签规则

### ⑤ 混合型

- 文字层 + 大量图表位图 + 标题位图，四种情况都有
- 全流程四层都要，实测样本即此类方向

## 层序为什么不能换

```
L1 改文字层  →  后面所有层的坐标基准是「新底版」
L3 换位图    →  L2 的覆盖坐标必须基于「换完位图后的底版」
L2 / L2b     →  都能改同一页的不同区域，顺序无关；但同一区域不要重叠
L4           →  必须对最终成品做，中间版本测没意义
```

L2 与 L2b 共享页坐标，**顺序可以互换**，但 L2b 的碰撞护栏是按源图邻块算的，
所以 L2b 排在 L2 之后更安全（此时 L2 的中文已经在图上，护栏判定更保守）。

## 分页尺寸陷阱

同一份 PDF 里不同页可以有不同 `MediaBox`。所有 bbox 都是**页内坐标**，
不要拿第一页的尺寸去换算别页。脚本里一律 `doc[pno].rect` 取当页尺寸。
